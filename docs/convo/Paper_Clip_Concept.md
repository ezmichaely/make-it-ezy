### What Paperclip actually is

Paperclip is essentially a **control plane for teams of AI agents**.

Their own distinction is basically:

> **OpenClaw = employee**  
> **Paperclip = company**

It doesn't primarily *make* the agents. Instead, it organizes agents such as **Claude Code, Codex, Cursor, OpenCode, Gemini CLI, Pi, Hermes, OpenClaw**, etc. into an organization. 

So you can have something like:

```text
                    COMPANY
                       │
                      CEO
                       │
        ┌──────────────┼──────────────┐
        │              │              │
       CTO          Research       Marketing
        │              │
   ┌────┴────┐      ┌──┴───┐
   │         │      │      │
 Coder    Reviewer  Web   Analyst
```

And Paperclip handles things like:

- **Agents / employees**
- **Org hierarchy**
- **Goals**
- **Task delegation**
- **Heartbeats**
- **Budgets & token spending**
- **Permissions / governance**
- **Skills**
- **Schedules**
- **Run history**
- **Agent coordination**
- **Different AI runtimes through adapters** 

And the interesting part:

**Paperclip doesn't actually need to be the intelligence.**

It calls external runtimes through adapters. For example, a heartbeat can cause Paperclip to invoke Claude Code or Codex, capture the result/cost, and record the run.

| Main concern | Org, governance, budgets | Choosing the right capability |
| Runtime | External agents | Potentially external agents |
| Skills | Shared organizational capability | Core building blocks |

Paperclip is **much higher-level**.

Their README explicitly describes itself as **not an agent framework** and not merely a workflow builder; it is the organizational/control layer above agents. 

And that's where this gets interesting for **Make It Ezy**.

Because if you're building Ezy as a **cost-efficient skill/agent selection and execution layer**, Paperclip could potentially become something Ezy **plugs into**, rather than something Ezy competes with.
